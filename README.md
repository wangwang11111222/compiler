# Tiger Language Compiler

A complete compiler for the Tiger language, written in Java on top of ANTLR 4.
It covers the full pipeline: lexing, parsing, semantic analysis, IR generation,
data-flow analysis, simple value numbering, three register-allocation
strategies, and MIPS-style assembly emission.

## Overview

The compiler is driven by a single executable (`cs8803_bin/tigerc`) and is
operated in **two passes**:

1. **Front end** — parse a `.tiger` source file and emit the intermediate
   representation (`.ir`) plus optional token / parse-tree / symbol-table dumps.
2. **Middle and back end** — read a `.ir` file back in, run data-flow analysis
   and optimization, allocate registers, and emit assembly.

The second pass reads its input from the `-r <irfile>` flag, not from the
`.tiger` source. Running an analysis or codegen flag without `-r` will fail,
because no IR has been loaded (see [Usage](#usage)).

## Architecture

```text
  benchmark1.tiger
        |
        v
  +-------------------+
  |  ANTLR 4 Lexer    |  Tiger.g4 -> TigerLexer / TigerParser
  |  ANTLR 4 Parser   |  (-s tokens, -p parse tree as .gv)
  +-------------------+
        |  parse tree
        v
  +-------------------+
  | SemanticChecker   |  scope + type checking
  | SymbolTable       |  (-t symbol table dump)
  +-------------------+
        |
        v
  +-------------------+
  | IRGenerator       |  three-address code
  +-------------------+  (-i writes benchmark1.ir)
        |
   =====|=========  PASS BOUNDARY: re-enter with -r benchmark1.ir  =====
        |
        v
  +-------------------+
  | DataFlowAnalyzer  |  basic blocks, CFG, liveness, spill costs
  +-------------------+  (-d writes .dataflow.json)
        |
        v
  +-------------------+
  | SVN               |  simple value numbering: constant folding,
  +-------------------+  lexical + value identity  (-x, prints a report)
        |
        v
  +-------------------------------------+
  | AllocationEmit                      |
  |   -n naive        -> .naive.s       |
  |   -l local per-BB -> .ib.s          |
  |   -g Briggs color -> .briggs.s      |
  |   -b interference graph (with -g)   |
  +-------------------------------------+
        |
        v
  MIPS-style assembly
```

The `Tiger*.java` files are regenerated from `Tiger.g4` by the Makefile and are
checked in only for convenience. The `_old` / `_od` files and the two standalone
helpers are historical and are **not** referenced by the build: the Makefile
compiles `src/Main.java` with `-cp src`, so `javac` pulls in only the classes
`Main` actually reaches.

## Requirements

| Requirement | Version / notes |
| --- | --- |
| JDK | 8 or newer (`javac`, `java`, `jar` on `PATH`) |
| ANTLR | 4.13.2 complete JAR |
| GNU Make | any recent version |
| POSIX shell | the Makefile uses `mkdir -p`, `chmod`, and writes an `sh` wrapper |
| SPIM or MARS | optional, to run the emitted MIPS-style assembly |

The Makefile expects the ANTLR JAR at `/usr/local/lib/antlr-4.13.2-complete.jar`.
Override it if yours lives elsewhere:

```bash
make ANTLR=/path/to/antlr-4.13.2-complete.jar
```

## Build

```bash
make
```

This will:

1. Run ANTLR over `Tiger.g4` to regenerate the `Tiger*` sources into `src/`.
2. Unpack the ANTLR runtime into `build/` so it can be bundled.
3. Compile the sources into `build/`.
4. Package `cs8803_bin/tigerc.jar` and write the `cs8803_bin/tigerc` wrapper
   script that invokes it.

To clean generated artifacts:

```bash
make clean
```

The output directory is named `cs8803_bin` after the course code this project
was originally built for; the name is kept as-is so existing scripts and
recorded results stay valid.

## Usage

### Pass 1 — front end and IR

```bash
./cs8803_bin/tigerc -f examples/benchmark1.tiger -s -p -t -i
```

Produces, next to the input file:

- `benchmark1.tokens` — token stream (`-s`)
- `benchmark1.tree.gv` — Graphviz parse tree (`-p`)
- `benchmark1.st` — symbol table dump (`-t`)
- `benchmark1.ir` — three-address IR (`-i`)

### Pass 2 — analysis, optimization, and codegen

```bash
./cs8803_bin/tigerc -f examples/benchmark1.tiger -r examples/benchmark1.ir \
    -d -x -n -l -g -b
```

Produces:

- `benchmark1.dataflow.json` — data-flow results (`-d`)
- an SVN report on stdout (`-x`)
- `benchmark1.naive.s`, `benchmark1.ib.s`, `benchmark1.briggs.s` (`-n`, `-l`, `-g`)
- Graphviz interference / coloring graphs (`-b`, effective only alongside `-g`)

Output paths are always derived from the `-f` input file's base name, so `-f` is
required in both passes.

### Flags

| Flag | Argument | Effect |
| --- | --- | --- |
| `-f` | file | Tiger source file. Required; also determines all output paths. |
| `-r` | file | IR file to load. Required for `-d`, `-x`, `-n`, `-l`, `-g`, `-b`. |
| `-s` | | Dump the token stream to `<base>.tokens`. |
| `-p` | | Dump the parse tree as Graphviz to `<base>.tree.gv`. |
| `-t` | | Dump the symbol table to `<base>.st`. |
| `-i` | | Generate IR and write `<base>.ir`. |
| `-d` | | Run data-flow analysis and write `<base>.dataflow.json`. |
| `-x` | | Run simple value numbering and print a report to stdout. |
| `-n` | | Naive register allocation, emit `<base>.naive.s`. |
| `-l` | | Local per-basic-block allocation, emit `<base>.ib.s`. |
| `-g` | | Briggs graph-coloring allocation, emit `<base>.briggs.s`. |
| `-b` | | Export interference and coloring graphs; only fires together with `-g`. |
| `-D` | file | Accepted and parsed by the CLI, but currently unused. |

Any unrecognized argument causes the driver to print an error and exit with
status 1.

### Exit codes

| Code | Meaning |
| --- | --- |
| 0 | Success |
| 1 | Missing input file, unreadable file, or unknown argument |
| 2 | Lexical error |
| 3 | Syntax error |
| 4 | Semantic error |

## Notes

- **The `-r` flag is not optional for the second pass.** Passing `-n`, `-l`, or
  `-g` without `-r` throws a `NullPointerException`, because the allocator runs
  against data-flow state that was never populated. Likewise `-d` and `-x` are
  silently no-ops without `-r`. Always follow the two-pass flow shown above.
- `-b` is nested inside the `-g` code path, so requesting the interference graph
  without Briggs allocation has no effect.
- The generated `Tiger*.java` files are overwritten by `make`; edit `Tiger.g4`
  rather than the generated sources.
- `results.csv` and `stats_summary.csv` are recorded measurement outputs from
  benchmark runs (allocation strategy, instruction counts, memory references,
  and SVN optimization counts). They are data, not build inputs.
- The emitted assembly is MIPS-style and is intended for a simulator such as
  SPIM or MARS.
